```mermaid
flowchart TB
    subgraph SRC["수집 · Source Adapters"]

        SR["사람인 API<br/>일 500회 한도"]
        WN["워크넷 API"]
    end

    DEDUP["중복 제거<br/>state.db"]

    subgraph RANK["랭킹 2단계"]
        E1["1차: 임베딩 유사도<br/>bge-m3 · 가중 최대"]
        E2["2차: Cross-encoder<br/>bge-reranker-v2-m3<br/>raw 로짓"]
    end

    GEN["요약 생성<br/>Claude"]
    VER{"faithfulness 검증<br/>GPT-5.6 Luna<br/>≥ 0.7?"}
    REGEN["재생성<br/>미근거 주장 주입<br/>최대 2회"]

    subgraph PUB["발행"]

        HUGO["Hugo → GitHub Pages<br/>papers 전용"]
    end

    FB["feedback.jsonl"]
    PROF["프로파일 가중치 갱신<br/>±0.1 클램프"]

    AX --> DEDUP
    SR -.->|"publish_scope=private"| DEDUP
    WN -.-> DEDUP
    DEDUP --> E1 --> E2 --> GEN --> VER
    VER -->|"통과"| PUB
    VER -->|"미달"| REGEN --> GEN
    REGEN -.->|"2회 초과"| FLAG --> PUB
    PUB --> TG --> FB --> PROF
```

**빨간색 = 게이트** (통과 못 하면 진행이 막힘) · **노란색 = 비공개 전용** (공개 싱크 도달 시 예외)

## 2. 채널이 갈리는 세 지점

두 채널은 같은 파이프라인을 쓰지만 **세 곳에서 반드시 갈립니다.** 섞으면 법적 문제가 됩니다.

```mermaid
flowchart LR
    subgraph P["papers"]
        P1["초록 전문<br/>수백 단어"] --> P2["내용 요약"] --> P3["faithfulness 검증"] --> P4["텔레그램 + 공개 사이트"]
    end
    subgraph J["jobs"]
        J1["제목·키워드·코드값<br/>본문 없음"] --> J2["적합도 판단<br/>+ 추천 사유"] --> J3["필터 위반 검사<br/>대조할 원문이 없음"] --> J4["텔레그램만<br/>공개 금지"]
    end
```

사람인 API는 **직무내용 본문을 반환하지 않습니다.** 대조할 원문이 없으므로 faithfulness 지표가
성립하지 않습니다 — 그래서 jobs 에는 붙이지 않고 하드 필터 위반 검사로 대체합니다.

## 3. 아이템 수명주기 (하루치 유실 방지)

```mermaid
stateDiagram-v2
    [*] --> collected: 수집 성공
    collected --> published: 발행 성공
    collected --> collected: 발행 실패 → 다음 실행 후보로 되살아남
    published --> [*]
```

`collect` 직후를 "끝"으로 마킹하면, 전 구간 실행에서 발행이 실패한 날의 아이템이
영영 후보에 오르지 못합니다. Actions 크론은 반드시 실패하는 날이 오므로 수집과 발행을
분리했습니다.

## 4. 게이트 지도

```mermaid
flowchart TB
    subgraph LEGAL["법적 게이트 ★"]
        G1["test_jobs_never_committed<br/>공고 원문 커밋 차단"]
        G2["test_no_secret_leak<br/>키 문자열 스캔"]
        G3["test_secret_redaction<br/>런타임 예외의 키 유출"]
        G4["test_no_fulltext_stored<br/>arXiv PDF 저장 차단"]
        G5["test_arxiv_single_connection<br/>3초·단일 커넥션"]
        G6["assert_public_scope<br/>비공개 아이템 유출 차단"]
    end
    subgraph REPRO["재현성 게이트"]
        R1["test_eval_models_are_revision_pinned<br/>모델 커밋 해시 고정"]
        R2["test_profile_parity<br/>영·한 프로파일 동일성"]
        R3["test_verifier_differs<br/>생성자·검증자 계열 분리"]
        R4["test_actions_requirements<br/>운영·평가 의존성 분리"]
    end
    classDef g fill:#5a1e1e,stroke:#f85149,color:#fff
    class G1,G2,G3,G4,G5,G6 g
```

`test_no_secret_leak` 은 **파일에 하드코딩된** 키만 잡습니다. 런타임에 예외를 타고
나가는 키는 못 잡아서 `test_secret_redaction` 을 따로 뒀습니다 — 실제로 봇 토큰이
공개 원장으로 새는 경로를 찾아 막은 뒤 추가한 게이트입니다.

## 5. 골드셋 라벨링 (평가 정답셋)

```mermaid
flowchart LR
    C["후보 719건"] --> T{"1패스<br/>제목"}
    T -->|"무관"| N["basis: title"]
    T -->|"보류"| K["2패스 대상"]
    T -->|"초록 펼침"| A["basis: abstract"]
    K --> R{"2패스<br/>초록"} --> RA["basis: abstract"]
    N -.->|"표본 40건"| RC["recheck<br/>1패스 누락률 실측"]
```

`basis` 를 남기는 이유: 제목만 보고 내린 판정과 초록까지 읽고 내린 판정을 구분해야
"제목 트리아지가 몇 %를 놓치는가"를 나중에 **측정**할 수 있습니다. 추정이 아니라 수치로.
