# 06 주 지표 결정 — nDCG@10 (Hit@5 는 포화)

> 결정 2026-09-18 · 결정자 한의정 · 코드 `eval/run_eval.py` · 테스트 `tests/test_eval_metrics.py`
> 관련: [05_골드셋_풀링.md](./05_골드셋_풀링.md) §5.3 · [라벨링_기준_2.md](./라벨링_기준_2.md) §1

## 1. 관측 — 관련 비율이 가정의 수십 배

2026-08-12 의 기존 라벨 51건은 셔플 순서의 앞 51건, 즉 **후보 719건에서 뽑은 무작위 표본**입니다.

| 판정 | 건수 |
|:--|--:|
| 관련 | 16 (31%) |
| 보류 (재검토 대기) | 33 |
| 무관 | 2 |

기획안 §9 는 하루 3~7건(약 1%)을 가정했습니다. 16/51 의 95% 구간은 20~45% 이고, 719건으로
환산하면 **하루 150~320건**이 정답입니다. 판정이 사실상 "관심사 16개 중 하나에 닿는가" 로
이뤄지고 있었다는 뜻입니다.

## 2. 무엇이 문제인가

정답이 하루 수십~수백 건이면 지표가 이렇게 됩니다.

| 지표 | 정답 비율 30% 에서 | 조건을 가를 수 있나 |
|:--|:--|:--|
| Hit@5 | 무작위 랭커도 `1 − 0.69⁵ = 0.84`. 실제 랭커는 전부 1.0 | ✗ |
| MRR | 1위가 거의 항상 정답 → 1.0 | ✗ |
| **nDCG@10** | IDCG 가 `min(\|G\|,10) = 10` 으로 고정되고, 상위 10 의 정답 **개수와 위치**를 봄 | ✓ |
| P@10 (보조) | 상위 10 중 정답 비율. 상한 1.0 | ✓ |

## 3. 두 갈래와 선택

| | (a) 기준을 좁힌다 | (b) 기준 유지 + 지표 전환 ← **선택** |
|:--|:--|:--|
| 관련의 정의 | "내일 아침 텔레그램 5건 안에 들어왔다면 링크를 눌렀을까" | "관심사 16개 중 하나에 닿는가" |
| 기존 라벨 51건 | 관련 16건 전부 재판정 | **그대로 유효** |
| 주 지표 | Hit@5 살아남음 | nDCG@10 |
| 대가 | 라벨링을 또 되돌림 (이미 3주간 51건) | "상위 5건이 유용했나" 를 이 골드셋으로는 못 물음 |

**선택 근거**: 라벨링이 이 프로젝트의 유일한 병목이고, (a)는 그 병목을 한 번 더 늘립니다.
"닿는가" 는 라벨러의 실제 판정 습관이라 재현성도 (b)가 높습니다 — 기준과 행동이 어긋나면
3개월 뒤의 본인이 다르게 판정합니다.

## 4. 코드에 반영한 것

- `precision_at_10()` — 보조 지표 P@10. `|G|` 로 정규화하지 않는 "상위 10 중 정답 비율"
- results.md 표에 `P@10` 열 추가. 열은 **지표 열 뒤에** 붙였습니다 — 앞에 끼우면 열 위치로
  값을 읽는 테스트가 조용히 다른 지표를 읽습니다
- 표 위에 **주 지표는 nDCG@10** 배너. Hit@5·MRR 은 §5.4 요구라 계산·기록하되 인용 금지
- 전 조건 평균이 `0.99` 이상인 지표에 **⚠ 포화** 경고 (`_saturated_metrics`).
  **nDCG@10 까지 포화하면** 기준을 좁혀 골드셋을 다시 만들어야 한다는 신호입니다
- 베이스라인 대비 개선폭 표는 `ΔnDCG@10` 을 첫 열로

## 5. 기획안과의 관계

기획안_2 §5.4 의 세 지표는 **그대로 계산합니다** (§5.8 DoD 충족). 바뀐 것은 *무엇을 근거로
조건을 비교하는가* 이고, 이 문서가 그 근거입니다. §5.4 를 고친 게 아니라 해석을 고정했습니다.
