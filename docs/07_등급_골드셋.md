## 1. 측정 — 1일치로 평가를 돌려서 확인한 것

2026-08-12 (후보 719건, 라벨 161건, 관련 87건), 4조건, `bge_m3@5617a9f6` / `bge_reranker_v2_m3@953dc6f6`, mps.

| 조건 | nDCG@10 (주) | P@10 | MRR |
|:--|--:|--:|--:|
| baseline (어휘 매칭) | 0.508 | **0.600** | 0.333 |
| bge_m3 | 0.548 | 0.500 | 1.000 |
| bge_m3_rerank | 0.548 | 0.500 | 1.000 |
| bge_m3_ko | 0.509 | 0.500 | 1.000 |

세 가지가 드러났습니다.

### 1.1 임계값이 리랭커를 굶겼다 (버그)

`min_score_threshold: 0.42` 인데 1차 점수(가중 최대, `penalty_weight=1.0`)의 **최고값이 0.299** 입니다.
719건 전부가 걸러져 `select_stage1` 이 0건을 돌려주고, 리랭커는 **한 번도 돌지 않았습니다.**
그래서 `bge_m3_rerank` 가 `bge_m3` 와 소수점 네 자리까지 같은 값으로 표에 실렸습니다.
발행 파이프라인이 같은 설정이면 **매일 0건 발행**입니다. 아무것도 터지지 않았습니다.

- 조치: `data/profile.papers_3.yaml` 에서 임계값을 **명시적으로 끕니다** (`null`). 재설정은 §4.
- 재발 방지: `embedding_ranking(stats=...)` 이 1차 통과 건수를 세고, 0이면 results.md 가
  **⚠ 리랭커가 1차에서 0건을 받았습니다** 를 띄웁니다. "효과 없음" 과 "측정 안 함" 은 다릅니다.

### 1.2 1차 점수에 신호가 거의 없다

풀과 무관하게 뽑힌 표본으로 쟀습니다 — 풀 밖 무작위 50건 + 풀을 만들기 **전에** 찍은 39건
(셔플 순서의 앞쪽이라 사실상 무작위 표본).

| 표본 | 관련 | 무관 | AUC |
|:--|--:|--:|--:|
| **무작위 89건 (편향 없음)** | 44 | 45 | **0.567** |
| 풀 밖 무작위 50건만 | 21 | 29 | 0.525 |
| 풀 생성 전 39건만 | 23 | 16 | 0.606 |
| 라벨 161건 전체 (풀 편향 — 상위권 과대표집) | 87 | 74 | 0.598 |

관련 논문의 1차 점수 중앙값 0.122, 무관 0.128 — **무관이 더 높습니다.**
AUC 0.5 는 동전 던지기입니다.

### 1.3 원인은 기준의 폭이다 — 관련 비율 49%

무작위 89건 중 44건이 관련(**49%**). 719건 환산 약 355건입니다.
무작위 랭커의 기대 nDCG@10 ≈ 0.49 이므로, 위 표의 0.51~0.55 는 무작위와 구분되지 않습니다.
Hit@5 는 네 조건 모두 1.0 (⚠ 포화).

**랭커가 나쁘다는 증거도, 좋다는 증거도 아닙니다 — 측정이 안 되는 상태입니다.**
06 의 선택(넓은 기준 유지 + nDCG@10)은 31% 추정에서 내린 결정이었고, 실측 49% 에서는 성립하지 않습니다.

## 2. 왜 등급인가

| | 대안 | 판단 |
|:--|:--|:--|
| (a) | 기준을 좁혀 **재라벨링** | 관련 87건을 다시 판정해야 하는 건 (c)와 같은데, 넓은 기준의 라벨이 덮여 사라집니다. "기준을 좁히면 수치가 얼마나 바뀌나" 를 영구히 못 봅니다 |
| (b) | 2일치(247건) 더 라벨링하고 평균 | 날짜가 늘면 잡음은 줄지만 49%·AUC 0.57 은 구조적입니다. 같은 결론에 247건을 더 씁니다 |
| (c) | **2단계 등급** ← 선택 | 이미 찍은 라벨을 **보존하면서** 한 단계 더 가릅니다. 무관 55건은 다시 보지 않습니다 (좁은 기준 ⊂ 넓은 기준) |

## 3. 설계

```
관련(넓은 기준, 1패스·2패스)  →  2등급  내일 아침 5건 안에 있었으면 링크를 눌렀을 것 → 평가의 정답
                              →  1등급  관심사에 닿기는 하지만 열지는 않았을 것      → 기록으로 남김
무관 · 보류                   →  건드리지 않음
```

- 원장(`eval/labels.jsonl`): `basis: "grade"`, `grade: 1|2`, **`relevant` 은 True 그대로**.
  1등급을 무관으로 덮지 않는 이유가 §2 (a)와 (c)의 차이입니다
- `export`: 등급을 매기기 **시작한 날짜**는 관련 라벨 전부에 등급이 있어야 합니다. 절반만 매기면
  등급 없는 관련이 평가에서 조용히 오답으로 세어져, 낮은 수치의 원인이 라벨링 미완인지 랭커인지
  구분할 수 없습니다 → export 가 거부합니다
- `run_eval`: 등급이 있는 날은 `gold = {2등급}`, 없는 날은 넓은 '관련' 전체.
  results.md 가 **어느 정의로 쟀는지**와 두 건수를 함께 적습니다
- 포화 경고(06)·판정률 judged@10(05)은 그대로 작동합니다

## 4. 임계값 재설정 — 등급 뒤에 할 일 ★

지금 넓은 기준으로 "정답의 95%를 살리는 임계값" 을 잡으면 **0.07** 이고, 719건 중 678건이
통과합니다. 아무것도 걸러지지 않는 값이라 의미가 없습니다.

2등급 골드셋이 나오면:

1. 2등급 정답들의 1차 점수 분포를 뽑는다
2. **2등급의 95%를 살리는 점수**를 임계값으로 잡는다 (§5.7 의 원문 요구)
3. 그 임계값에서 하루 몇 건이 통과하는지 함께 기록한다 (발행량 = 비용)
4. 근거를 이 문서 §4 에 수치로 남기고 `profile.papers_4.yaml` 로 반영한다

**숫자 없이 임계값을 다시 채우지 마세요.** 0.42 가 그렇게 들어온 값입니다.

## 5. 실행

```bash
python -m eval.label grade --date 2026-08-12   # 3패스 — 관련 87건에 등급
python -m eval.label status                    # '2등급' 열과 미등급 경고
python -m eval.label export                    # summary.grades 포함
python -m eval.run_eval                        # 정답 = 2등급
```

  — **정의와 건수를 함께** 적습니다

- 리랭커 수치는 **임계값 수정 이후**의 것만 유효합니다

## 7. 남은 위험

- 2등급이 하루 5건 미만이면 Hit@5·MRR 의 분산이 큽니다. 날짜 3개 평균으로 보고, 단일 수치로 단정하지 않습니다
- 2등급이 **0건인 날**은 지표가 정의되지 않아 평가에서 제외됩니다 (§5.4). 제외 사실은 results.md 에 남습니다
- 등급도 1인 판정이고 시점 고정입니다 ([라벨링_기준_3.md](./라벨링_기준_3.md) §6)
- 2등급을 넉넉하게 주면 이 패스를 한 의미가 없습니다. 기준 문장은 "하루 5건 안에 들 만한가" 입니다
