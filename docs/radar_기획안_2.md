## 1. 목적과 성공 기준 (v1.0 §1에서 유지)

**두 가지를 동시에 달성합니다.**

| | 목적 | 성공 기준 |
|:--|:--|:--|
| 실사용 | 매일 아침 논문 5편 + 신규 채용공고 요약 수신 | 3개월 자동 실행, 실제로 읽게 되는 선별 품질 |
| 포트폴리오 | "도메인 무관 문서 파이프라인 + 검증 설계" 증명 | 랭킹 성능 정량치 + 90일 커밋 이력 + 공개 저장소 |

**포트폴리오 관점의 핵심 주장 3개.** 이게 없으면 이 프로젝트는 가치가 없습니다 —
수집·요약·발행만 하는 봇은 이미 수백 개 있습니다.

1. **선별을 검색 문제로 정의하고 정량 평가했다** — 하루 수백 건에서 5건. 임베딩 + 리랭커,
   Hit@5 / MRR / nDCG로 베이스라인 대비 개선폭 측정
2. **생성 결과를 다른 계열 모델로 검증하는 게이트를 넣었다** — 왜곡을 채점하고 미달 시 재생성
3. **사용 로그가 랭킹으로 환류된다** — 읽음/스킵 라벨로 프로파일 갱신

> **우선순위가 충돌하면 2번(포트폴리오)이 이깁니다.** 매일 도는 것보다 **측정치가 재현
> 가능한 것**이 중요합니다. 그래서 §9-3(리비전 고정) 같은 규칙이 존재합니다.

### 3.1 arXiv — 결론과 근거

| 대상 | 라이선스 | 우리가 하는 것 |
|:--|:--|:--|

## 4. 파이프라인 설계

### 4.1 전체 흐름

```
수집 → 중복제거 → 1차 랭킹(임베딩) → 2차 랭킹(리랭커) → 요약 → 검증 → 발행 → 피드백
                                                                              │
                        └───────────── 프로파일 가중치 갱신 ◄────────────────┘
```

**논문과 채용은 같은 파이프라인입니다.** 다른 것은 소스 어댑터와 출력 템플릿뿐입니다.
이 판단 자체가 포트폴리오의 일부입니다 — "왜 두 개를 따로 안 만들었나"에
"중간 4단계가 동일해서 어댑터로 분리했고, 세 번째 소스 추가에 X시간 걸렸다"로 답합니다.

**단 두 채널은 세 지점에서 갈립니다.** 이걸 섞으면 법적 문제가 됩니다.

| 지점 | papers | jobs |
|:--|:--|:--|
| LLM 역할 | 내용 요약 | **적합도 판단 + 추천 사유** (본문이 없음) |
| 검증 | faithfulness | **필터 위반 검사** (대조 원문 없음) |
| 발행 | 텔레그램 + 공개 사이트 | **텔레그램 + 비공개만** |

### 4.2 포트와 어댑터 (델타 §D6.2)

모든 외부 의존을 프로토콜로 분리하고 **Fake를 기본 대체재**로 둡니다.
`RADAR_MODE=fake`면 키 0개로 전 구간이 돌고 pytest가 통과합니다.

```
포트          구현체                                        키
─────────────────────────────────────────────────────────────
SourceAdapter arxiv ✓ / saramin / worknet / fake ✓          arxiv·fake 불필요
Embedder      openai / local_bge ✓ / hash_stub ✓            local·stub 불필요
Reranker      bge-reranker-v2-m3 ✓                          불필요
Generator     anthropic / fake ✓                            anthropic 필요
Verifier      openrouter / rulebased_fake ✓                 openrouter 필요
Sink          hugo ✓ / telegram / notion / file ✓           telegram 필요
```

> **`RADAR_MODE` 기본값은 `fake`가 아니라 `live`입니다.** 기본을 fake로 두면 운영에서
> 조용히 가짜 데이터를 발행할 수 있습니다. **키가 없어 죽는 게 가짜로 성공하는 것보다
> 낫습니다.**

### 4.4 원장 스키마 (`data/runs.jsonl`) — schema 1 확정

한 줄 = 한 실행. **기록된 줄은 절대 고치지 않습니다.**

```json
{
  "schema": 1,
  "run_id": "2026-08-12T07:00:00+09:00/papers",
  "channel": "papers",
  "stage": "collect|rank|summarize|publish|full",
  "profile": "data/profile.papers_1.yaml",
  "params": {"window_hours": 48, "min_collected": 300, "mode": "live", "pages_fetched": {"arxiv": 8}},
  "sources": {"arxiv": 719},
  "collected": 719,
  "after_dedup": 719,
  "stage1_top_n": null,
  "selected": null,
  "summaries": null,
  "gates": {"passed": true, "failures": []},
  "duration_sec": 27.901,
  "cost_usd": 0.0
}
```

**규칙 4개.**

1. `schema`는 **1입니다.** 올리지 마세요. 이 형태가 schema 1의 원형입니다
2. 실행하지 않은 단계는 **키 삭제가 아니라 `null`**. 리더가 KeyError를 내면 안 됩니다
3. `stage`는 5개 값만. 그 외는 `RunRecord`가 예외를 던집니다.
   **`summaries: []`(전 구간 돌았는데 0건 선정)와 `summaries: null`(수집만 함)의 구분이
   가동률 계산의 정확성을 결정합니다**
4. `profile`에 **실제로 로드한 경로**를 기록. 파일 번호 규칙 때문에 실행마다 달라질 수
   있고, 안 남기면 평가가 재현 불가입니다

`summaries[]` 항목 (M2에서 채움):

```json
{"item_id": "arxiv:2608.01234", "rank_score_stage1": 0.71, "rank_score_stage2": -2.51,
 "generator_model": "...", "verifier_model": "...", "faithfulness": 0.91,
 "retries": 0, "unsupported_claims": [], "flagged": false}
```

> `rank_score_stage2`는 **raw 로짓**입니다. sigmoid를 씌우면 무관한 항목이 전부 0 근처로
> 뭉쳐서 원장을 사람이 읽을 수 없습니다 (§9-4).

### 4.5 설정 로더 — 파일 번호 규칙 대응 ★

이 저장소는 파일을 고칠 때 덮어쓰지 않고 `_N`을 붙입니다. **코드가 경로를 하드코딩하면
구버전을 읽습니다.**

```python
# src/core/config.py — 이미 구현됨. 새로 만들지 마세요.
resolve_profile("profile.jobs")      # → data/profile.jobs_1.yaml (최고 번호)
load_profile("profile.papers")       # → (dict, Path)  ★ 경로를 함께 반환
```

- 접미사 없는 파일은 **0** (가장 오래된 것)
- 번호는 **정수 비교**. 문자열 정렬이면 `_10 < _9`가 되어 최신을 건너뜁니다
- `_숫자`만 인정. `profile.papers.ko.yaml`이 `profile.papers` 조회에 걸리면 **평가
  대조군이 운영에 로드됩니다**
- 로드 경로를 원장에 기록

### 5.1 만들 것


### 5.2 점수 합성 — 여기서 결정이 필요합니다

프로파일에 관심사 15개가 있고 각각 `weight`가 있습니다. 문서 하나당 점수 하나를
만들어야 합니다.

| 방식 | 계산 | 무엇을 왜곡하는가 |
|:--|:--|:--|
| **가중 최대** (권장) | `max_i(cos(d, q_i) × w_i)` | 하나의 관심사에 강하게 맞는 논문이 이깁니다. 여러 관심사에 약하게 걸치는 논문은 밀립니다 |
| 가중 평균 | `Σ cos × w / Σ w` | 모든 관심사에 고르게 애매한 논문이 이깁니다. **관심사가 15개라 희석이 심합니다** |
| 상위 k 평균 | `mean(top-3)` | 절충 |

**기본값은 가중 최대**입니다. 근거: 관심사 15개는 서로 독립적인 주제이고, "diffusion 편집"
논문이 "RAG 평가"와 유사할 이유가 없습니다. 평균을 쓰면 15개 중 14개의 낮은 유사도가
신호를 지웁니다.

**M1에서 두 방식을 다 재세요.** 조건이 하나 늘 뿐이고, "왜 최대를 골랐나"에 수치로
답할 수 있게 됩니다.

`exclude.soft`는 **감점**입니다(하드 배제 아님).

```python
penalty = max(cos(d, e_j) × p_j for j in exclude.soft)   # 가장 강하게 걸리는 것
score = base_score - penalty_weight * penalty            # penalty_weight는 M1에서 결정
```

> **exclude를 하드 배제로 바꾸지 마세요.** 경계 사례를 통째로 버리게 되고, 골드셋에
> 관련으로 라벨된 논문이 후보에서 사라지면 Hit@5의 상한이 내려갑니다.

### 5.3 임베딩 캐시 — 필수입니다

719건 × 4~5조건 × 3일치를 매번 인코딩하면 조건 하나 바꿀 때마다 수십 분입니다.

```
data/cache/emb/{model_id}_{revision[:8]}/{sha256(text)[:16]}.npy
```

- 키에 **모델 id와 리비전**이 들어갑니다. 모델을 바꾸면 캐시가 자동으로 갈립니다
- `data/cache/`는 이미 gitignore
- 무효화: 리비전이 바뀌면 새 디렉터리라 자동. 텍스트가 바뀌면 해시가 달라 자동

**이걸 안 하면 조용히 망가지는 것**: 조건 비교가 느려서 한두 개만 돌리고 끝냅니다.
v1.0 §9는 최소 3개를 요구합니다.

### 5.4 지표 — 정확한 정의와 엣지 케이스

날짜 `d`의 후보 풀에서 랭킹 리스트 `R = [r_1, ..., r_n]`, 정답 집합 `G_d`에 대해:

| 지표 | 정의 | 엣지 케이스 |
|:--|:--|:--|
| **Hit@5** | `1 if R[:5] ∩ G_d ≠ ∅ else 0` | `G_d = ∅`이면 **그날은 평가에서 제외**하고 제외 사실을 results.md에 기록 |
| **MRR** | `1 / rank(첫 정답)`. top-k 밖이면 **0** | 정답이 하나도 랭킹에 없으면 0 (`1/∞`가 아님) |
| **nDCG@10** | `DCG@10 / IDCG@10`, `DCG = Σ rel_i / log2(i+1)`, 이진 rel | `IDCG`는 `min(|G_d|, 10)`개의 정답이 최상위에 있을 때 값 |

**동점 처리**: 점수가 같으면 **item_id 사전순**으로 고정하세요. 정렬이 불안정하면
같은 조건을 두 번 돌렸을 때 수치가 달라집니다.

**날짜별로 계산하고 평균냅니다.** 전체를 하나의 풀로 합치면 안 됩니다 — 운영은 하루
단위로 돌기 때문입니다.

## 9. 함정 16개 — 전부 실측으로 확인한 것입니다 ★

이 목록이 이 문서에서 가장 값어치 있는 부분입니다. **문서에 없었기 때문에 밟았습니다.**
공통점은 하나입니다 — **전부 초록불로 위장했습니다.**

### 9.1 기본 인자에 모듈 상수를 쓰면 테스트가 실제 데이터를 읽습니다

```python
# ✗ 정의 시점에 바인딩된다. monkeypatch가 먹지 않는다
def load_candidates(date, candidates_dir: Path = CANDIDATES_DIR): ...

# ✓ 호출 시점에 해석
def load_candidates(date, candidates_dir: Path | None = None):
    path = (candidates_dir or CANDIDATES_DIR) / f"{date}.jsonl"
```

**증상**: 라벨링 테스트 17개가 통과. 실제로는 tmp가 아니라 `data/candidates/`의 719건을
읽고 있었습니다. 12건을 기대하는 테스트가 통과한 건 입력 키가 12개에서 끊겨 `q`로
종료됐기 때문입니다.
**조용히 망가지는 것**: 테스트 전체가 아무것도 검증하지 않습니다.
**재발 방지**: 새 테스트를 쓰면 **일부러 깨뜨려보고** 빨간불이 나는지 확인 (§10.4).

### 9.2 교차언어 수치 검증은 오탐이 납니다

영어 초록은 작은 수를 **단어로** 씁니다(`"six object detection models"`). 한국어 요약은
**숫자로** 씁니다(`"모델 6종"`). 모든 숫자를 대조하면 `6`, `2단계`의 `2`, `YOLOv5`의 `5`가
전부 "초록에 없는 수치"가 됩니다.

**증상**: 왜곡이 전혀 없는 정상 요약이 faithfulness 0.3점.
**조치**: 검사 대상을 **소수 · 백분율 · 세 자리 이상**으로 제한. 성능 수치는 거의 항상
이 셋 중 하나이고, 맨 두 자리 정수는 개수·차수·모델 버전입니다.
**남는 한계**: 초록 `0.768` vs 요약 `76.8%`는 여전히 불일치로 잡힙니다. 그래서
프롬프트가 "수치는 초록에 나온 그대로"를 요구합니다.

### 9.3 리비전을 고정하지 않으면 미머지 PR의 가중치가 로드됩니다 ★

`SentenceTransformer("BAAI/bge-m3")` — sentence-transformers 5.x는 safetensors를
선호하는데, bge-m3의 main에는 `pytorch_model.bin`만 있습니다. 그래서 **머지되지 않은
PR(`refs/pr/130`)에서 safetensors를 받아갑니다.**

**조용히 망가지는 것**: PR은 닫히거나 바뀝니다. 그 상태로 낸 Hit@5는 재현되지 않습니다.
**M1 수치가 이 프로젝트의 가치 전부인데(§1) 재현이 안 되면 의미가 없습니다.**
**조치**: `eval/models.yaml`에 40자 커밋 해시로 고정. `revision=` 인자로 전달.
**게이트**: `test_eval_models_are_revision_pinned`

### 9.4 CrossEncoder는 기본으로 sigmoid를 씌웁니다

| 설정 | 범위 | 표준편차 |
|:--|:--|--:|
| 기본값 | `+0.0000 ~ +0.0751` | 0.029 |
| `activation_fn=torch.nn.Identity()` | `-10.08 ~ -2.51` | 2.92 |

순위는 단조변환이라 동일합니다. **문제는 원장과 임계값입니다** — `0.0000`과 `0.0001`이
로짓으로는 -9.2와 -9.0입니다. 사람이 읽을 수 없고 임계값도 못 정합니다.
**조치**: 평가·원장에는 raw 로짓.

### 9.5 arXiv 구형 ID에서 아카이브 접두사가 날아갑니다

`http://arxiv.org/abs/math.GT/0309136v1`을 `rsplit("/", 1)[-1]`로 자르면 `math.GT/`가
사라져 `arxiv:0309136`이 됩니다. 다른 아카이브의 같은 번호와 충돌합니다.
**조치**: `/abs/` 뒤 **전체**를 사용.
**발생 확률**: 낮습니다(2007년 이전 ID). 하지만 충돌하면 중복 제거가 조용히 틀립니다.

### 9.6 후보 파일에 중복 줄이 생깁니다

`run_collect`는 후보 파일에 쓰고 **그다음** state.db에 마킹합니다. 사이에서 죽으면 다음
실행이 같은 아이템을 한 번 더 씁니다.
**조용히 망가지는 것**: 같은 논문이 라벨링에 두 번 나오고, 두 판정이 엇갈리면 골드셋 오염.
**조치**: 순서를 바꾸지 말고(그러면 크래시 시 영구 유실) **읽는 쪽에서 id로 접습니다.**

### 9.7 ★★ collect가 seen을 마킹하면 M3에서 하루치가 사라집니다 — 미해결

지금 `collect` 단계가 state.db에 `seen`을 씁니다. M0에서는 맞습니다(수집이 곧 끝).
**M3에서 전 구간을 돌리면 수집 직후 마킹되고, 이후 랭킹·요약·발행 중 하나라도 실패하면
그날 아이템은 이미 `seen`이라 영원히 후보에 오르지 않습니다.**

Actions 크론은 반드시 실패합니다(v1.0 §11이 이미 지연·실패를 전제).
**이건 아직 해결되지 않았습니다. §5(M3)에서 확정합니다.**
방향: `seen_items`에 `status` 컬럼(`collected` / `published`)을 두고, 다음 실행은
`published`가 아닌 것을 다시 후보에 넣습니다.

### 9.8 `connection` 필드를 faithfulness에 넣으면 지표가 무의미해집니다

요약의 `connection`("내 프로젝트와의 연결점")은 **독자의 맥락에서 나오는 판단**이라

### 9.14 `time.sleep(3)`으로는 arXiv 약관을 못 지킵니다

약관은 **두 개**입니다 — 3초 간격 **그리고 단일 커넥션**. 슬립 루프는 한 프로세스의
순차 호출만 지킵니다. 프로세스가 둘이면 그 순간 커넥션이 2개입니다.
**조치**: 파일락(`data/.arxiv_lock`)을 쥔 상태에서만 요청을 엽니다.
**남는 한계**: 파일락은 **같은 머신만** 묶습니다. 로컬 맥과 Actions 러너는 못 묶습니다.
→ **운영 규칙으로만 막힙니다: "로컬에서 수집을 돌리기 전 Actions 스케줄을 끌 것."**
구조적으로 막을 수 없는 것을 막았다고 쓰지 마세요.

### 9.15 arXiv 초록의 10%에 LaTeX 중괄호가 있습니다 — 프롬프트 템플릿이 깨집니다

실측 (2026-08-12 수집분 719건):

```
중괄호 포함: 72/719 (10.0%)
  "...the first to introduce \textbf{meta-detection} into AI-gene..."
  "...bounds to \[ \frac{6π}{11} \;\le\; K_G \;\le\; ..."
```

`prompts/paper.md`는 `{title}` · `{abstract}` · `{interests}` 자리표시자를 씁니다.

**안전한 것**: `template.format(abstract=abstract)` — 치환**값** 안의 중괄호는 해석되지 않습니다.
**깨지는 것**:
- 치환한 결과 문자열을 **한 번 더** `.format()` 하거나 f-string에 넣기 → `KeyError: '6π'`
- 치환 후 남은 자리표시자를 정규식으로 검사하기 → 초록의 `{...}`를 미치환으로 **오탐**
- `str.replace()`로 치환하면서 `{`를 이스케이프한다고 가정하기

**조치**: 치환은 **1회, `.format()` 또는 `string.Template`으로만.** 미치환 검사가 필요하면
**치환 전 템플릿**에서 하세요. 치환 후 텍스트는 검사하지 마세요.
**조용히 망가지는 것**: 10편 중 1편이 요약 단계에서 예외로 죽고, 그 아이템은 어느 제외 사유에도
안 잡혀서 원장에 이유 없이 사라집니다.

## 13. 포트폴리오 연결 — 최종 목표 문장

3개월 운영 후 **측정치와 함께** 쓸 수 있어야 하는 문장들입니다.
이 문장들이 나오지 않는 구현은 방향이 틀린 것입니다.

- 하루 N건에서 5건을 선별하는 랭킹 레이어 — 베이스라인 대비 Hit@5 X% → Y%
- 생성자와 검증자를 분리한 faithfulness 게이트 — 평균 Z, 재생성률 W%
- 90일 무중단 자동 실행 — 성공률 N%, 건당 비용 $X
- 소스 어댑터 패턴으로 2개 도메인 지원 — 신규 소스 추가 X시간

**README와 이력서에는 "만들었다"가 아니라 위 수치를 씁니다.**

여기에 이번 구현에서 추가로 확보한 것들:

- **1패스 라벨링 누락률 실측** — "제목만 보고 놓쳤을 수 있다"를 숫자로
- **교차언어 손실 실측** — 영/한 프로파일 × (선택) 임베딩 모델
- **규칙 검증자를 LLM 검증자의 하한선 베이스라인으로** — "LLM 검증이 규칙 대비 얼마나 나은가"
