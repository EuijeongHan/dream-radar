# 연구 인사이트 원장

Radar가 발견한 논문 중 **나중에 모델·에이전트 개발에 재사용할 가치가 있는 아이디어와 코드**를 누적하는 목록입니다. 카드뉴스는 대외 설명용이고, 이 문서는 내부 개발 판단용입니다.

구조화 원본은 [`data/research_insights.jsonl`](../data/research_insights.jsonl)입니다. 한 논문당 한 줄을 append-only로 추가합니다.

## 기록 규칙

1. 논문 주장과 Radar의 해석을 분리합니다.
2. 코드 저장소는 실제 존재 여부와 라이선스를 확인합니다.
3. `adopt`는 즉시 도입, `experiment`는 격리 실험, `watch`는 관찰, `reject`는 보류를 뜻합니다.
4. 코드를 발견했다고 바로 의존성에 추가하지 않습니다. 라이선스·보안·유지보수 상태를 먼저 검토합니다.
5. 새 카드뉴스를 만들 때 해당 논문의 항목을 함께 추가하고, 후속 검토 결과는 같은 `item_id`의 새 버전으로 남깁니다.

## 목록

### 001 — AgentRewind: Recoverable Execution for Long-Horizon LLM Agents

- arXiv: [2608.14380](https://arxiv.org/abs/2608.14380)
- 검토 기준: 초록 + 공개 저장소 확인
- 판단: `experiment`
- 핵심 인사이트:
  - 긴 작업의 신뢰성은 오류 예방만으로 충분하지 않고 오류 이후 복구 능력도 필요합니다.
  - 에이전트 컨텍스트와 외부 환경 상태를 같은 시점으로 묶어야 복구 가능한 체크포인트가 됩니다.
  - 완전 성공률 외에 체크리스트 기반 부분 진척도를 측정하면 실패 실행에서도 정보를 얻을 수 있습니다.
  - 재시작 시 과거 시도의 유용한 정보를 유지하면 처음부터 반복하는 비용을 줄일 수 있습니다.
- Radar 적용 후보:
  - 파이프라인 단계별 체크포인트와 재개 토큰
  - 게시 직전 상태와 외부 부작용을 분리한 실행 원장
  - 실패 후 전체 재실행 대신 마지막 안전 단계부터 재개
  - 테스트를 단일 pass/fail뿐 아니라 단계별 체크리스트 진척도로 기록
- 공개 코드:
  - [Futuresis/replay-agent-recorder](https://github.com/Futuresis/replay-agent-recorder) — 실행 기록·재현·분기·상태 복구 도구, MIT, alpha. 직접 의존 전 격리 실험 필요.
  - [Kelvin-Coffee/MettleBench](https://github.com/Kelvin-Coffee/MettleBench) — 82개 장기 엔지니어링 작업 벤치마크, Apache-2.0. Radar용 체크리스트 평가 설계 참고 후보.
- 다음 실험:
  - Fake 파이프라인의 `collect → rank → summarize → publish` 사이에 체크포인트를 넣고, publish 실패 후 summarize를 재호출하지 않고 재개할 수 있는지 검증합니다.

### 002 — InferenceBench: A Benchmark for Open-Ended LLM Inference Optimization by AI Agents

- arXiv: [2607.20468](https://arxiv.org/abs/2607.20468)
- 검토 기준: 논문 본문 + 공식 공개 저장소
- 판단: `experiment`
- 핵심 인사이트:
  - 에이전트가 관련 최적화 기법을 언급할 수 있어도 실제 실행에서는 탐색 폭이 매우 좁을 수 있습니다.
  - 더 긴 실행 예산이 자동으로 더 나은 탐색이나 최종 결과로 이어지지 않습니다.
  - 개발 중 좋았던 설정을 찾는 것과 종료 시점에 재실행 가능한 정상 산출물을 남기는 것은 별개의 능력입니다.
  - 에이전트 평가는 성능뿐 아니라 품질, 무결성, 깨끗한 환경에서의 재현성을 함께 게이트로 두어야 합니다.
- Radar 적용 후보:
  - 요약·랭킹 전략마다 최소 탐색 다양성을 요구하는 후보 생성 단계
  - 각 후보의 점수, 실패 이유, 비용을 비교하는 실험 원장
  - 실행 중 최고 결과와 마지막 결과를 분리해 보존하는 best-known checkpoint
  - 평가 데이터 오염이나 편법을 검사하는 무결성 게이트
- 공개 코드:
  - [aisa-group/InferenceBench](https://github.com/aisa-group/InferenceBench) — 오픈엔디드 LLM 추론 최적화 평가 하네스, Apache-2.0. H100·컨테이너 기반이라 Radar에 직접 의존시키기보다 평가 설계와 실행 원장 구조를 우선 참고합니다.
- 다음 실험:
  - Radar 랭킹 단계에서 서로 다른 세 가지 후보 전략을 의무 생성하고, 동일한 평가 예산으로 단일 전략 반복 대비 선택 품질과 비용이 개선되는지 비교합니다.

### 003 — Agent Memory Is a Surface for Endogenous Authorization Laundering

- arXiv: [2609.01836](https://arxiv.org/abs/2609.01836)
- 검토 기준: 논문 본문 + 공식 공개 저장소
- 판단: `experiment`
- 핵심 인사이트:
  - 지속 기억은 단순 성능 구성요소가 아니라 에이전트가 실제로 적용하는 권한 정책의 일부입니다.
  - 증분 요약은 정상적인 입력만으로도 철회·범위·출처를 왜곡해 거짓 권한을 만들 수 있습니다.
  - 기억 오류의 생성과 실행기의 행동 전파를 분리해 측정해야 실패 원인을 정확히 찾을 수 있습니다.
  - 출처 검증과 이벤트 소싱은 안전성을 높이지만 정상 권한을 거부하는 비용을 함께 측정해야 합니다.
- Radar 적용 후보:
  - 게시·외부 저장 등 부작용 권한을 자연어 기억과 분리한 결정론적 권한 원장
  - 승인에 주체·대상·범위·유효기간·출처 이벤트를 필수 필드로 저장
  - 권한 변경을 append-only 이벤트로 남기고 현재 상태는 코드로 재구성
  - 실행 직전 원장 재검증과 허용·거부 양쪽 오류율 측정
- 공개 코드:
  - [tommasocerruti/eal-bench](https://github.com/tommasocerruti/eal-bench) — 권한 기억 오류를 구매·사이버보안·금융에서 평가하는 Python 벤치마크. 논문은 CC BY 4.0이지만 저장소에 별도 소프트웨어 라이선스가 확인되지 않아 코드는 참고·검토만 하고 복제·통합하지 않습니다.
- 다음 실험:
  - Radar의 publish 승인을 자연어 대화 상태와 분리된 append-only 이벤트로 기록하고, 승인 후 대상·캡션·파일이 바뀌면 실행을 자동 거부하는 테스트를 추가합니다.
