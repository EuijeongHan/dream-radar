## 1. 이 골드셋이 답하려는 질문

**"내가 그날 아침에 실제로 읽었을 논문인가."**

"좋은 논문인가"도 "인용이 많을 논문인가"도 아닙니다. 이 시스템은 개인화 랭커이고,
정답은 **이 사람이 읽고 싶어 했는가**입니다. 그래서 1인 라벨러가 한계가 아니라 정의입니다
(기획안 §11의 프레이밍과 같습니다).

판정이 흔들릴 때 돌아올 기준 문장:

> 이 논문이 내일 아침 텔레그램 5건 안에 들어왔다면, 나는 링크를 눌렀을까?

## 2. 절차

### 2.1 무엇을 라벨링하나 — 다중 시스템 풀링 (`_1` 에서 변경)

하루 후보가 700~1,100건인데 관련 논문은 한 자릿수입니다. 처음에는 전수 라벨링으로
설계했지만 3주 동안 51건(1일치의 5%)에서 멈췄습니다. **끝나지 않는 골드셋은 평가를
영영 막습니다.**

그렇다고 **랭커 하나로 상위 N건을 뽑아 그것만 라벨링하면 평가가 무너집니다** (기획안_2
§9.11) — 평가 대상인 랭커가 정답셋의 범위를 정하게 되어, 그 랭커가 놓친 논문은 애초에
정답이 될 기회가 없습니다. 그래서 TREC 이 쓰는 **다중 시스템 풀링**으로 바꿨습니다.

- 비교하는 4조건(`baseline` · `bge_m3` · `bge_m3_rerank` · `bge_m3_ko`) **각각의 상위 30**을
  합칩니다. 어휘 매칭 베이스라인과 한국어 프로파일이 들어 있어서, 영어 임베딩 하나의
  취향으로 범위가 정해지지 않습니다
- 풀 **밖**에서 **무작위 50건**을 더 넣습니다 — 4조건이 모두 놓친 정답이 얼마나 되는지
  재기 위해서입니다 (`goldset.yaml` 의 `summary.pooling.estimated_missed`)
- 라벨링 화면에는 **순위도, 어느 조건이 뽑았는지도 보이지 않습니다.** 셔플 순서 그대로,
  무작위 표본과 섞여 나옵니다

왜 이게 §9.11 에 걸리지 않는지, 무엇을 잃는지는 [05_골드셋_풀링.md](./05_골드셋_풀링.md).
하루 풀 크기의 실측도 거기 있습니다.

풀을 만들기 **전에** 찍은 라벨은 풀 밖이어도 그대로 유효하고, 작업 목록에도 남습니다.

→ **풀 안에서는 여전히 읽는 깊이를 2단계로 나눕니다.**

| 패스 | 보는 것 | 판정 | 기록 |
|:--:|:--|:--|:--|
| 1 | 제목 + 카테고리 | 무관 확정 / 보류 | `basis: title` |
| 2 | 초록 전문 | 관련 / 무관 | `basis: abstract` |

1패스에서 거른 것도 **정식 라벨(`relevant: false`)** 입니다. 다만 `basis`를 남겨서
나중에 "제목만 보고 놓친 게 아닌가"를 검증할 수 있게 합니다.

**1패스의 질문은 "관련 있는가"가 아니라 "초록을 읽을 가치가 있는가"입니다.**
확신이 없으면 무조건 보류(`k`)입니다. 1패스에서 잘못 버린 논문은 영원히 정답이 될 수
없지만, 잘못 보류한 논문은 2패스에서 걸러집니다. **비대칭이므로 보류 쪽으로 기울이세요.**

제목만으로 판단이 안 서는데 지금 궁금하면 **`a`로 초록을 펼쳐 그 자리에서 y/n/k 판정**할
수 있습니다. 이때 판정은 `basis: abstract`로 기록됩니다 — 초록을 읽고 내린 판정을
`basis: title`로 남기면 재검토(§2.4)의 누락률 측정이 오염되기 때문입니다.
단 `a`를 남발하면 1패스의 속도 이점이 사라지니, 기본은 여전히 `k`입니다.

### 2.2 순서를 섞는 이유

도구가 후보를 날짜별 고정 시드로 섞어서 보여줍니다. arXiv 제출 순서 그대로 라벨링하면
뒤로 갈수록 집중력이 떨어지는 효과가 **특정 카테고리에 체계적으로** 몰립니다(제출 시각과
분야에 상관이 있으므로). 섞으면 피로 효과가 편향이 아니라 잡음이 됩니다.
시드가 날짜에서 나오므로 중단 후 재개해도 순서는 같습니다.

풀이 있어도 **같은 순서에서 풀 밖 항목만 빠집니다.** 랭킹 기여분과 무작위 표본이 섞여
나오므로 지금 보는 논문이 어느 쪽인지 알 수 없습니다 — 알면 판정이 기울어집니다.

### 2.3 명령

```bash
python -m eval.pool                              # 0 — 풀 만들기 (날짜마다 1회. 다시 돌려도 덧붙이기만)
python -m eval.label triage  --date 2026-08-12   # 1패스 (풀 안만)
python -m eval.label review  --date 2026-08-12   # 2패스
python -m eval.label recheck --date 2026-08-12   # 1패스 누락률 측정 (표본 40건)
python -m eval.label status                      # 진행률
python -m eval.label export                      # eval/goldset.yaml 생성
```

언제든 `q`로 나가면 그 지점까지 저장됩니다. `u`는 직전 판정 취소입니다.

### 2.4 `recheck` — 1패스를 스스로 검증하는 단계 ★

1패스는 제목만 봅니다. 제목이 불친절한 논문을 놓쳤을 수 있고, **놓쳤는지 아닌지를 모르면
§6의 한계 2가 영원히 "그럴 수도 있다"로 남습니다.**

`recheck`는 1패스에서 버린 것 중 **표본 40건**을 뽑아 초록까지 읽게 합니다. 표본에서
몇 건이 뒤집히는지가 곧 1패스 누락률의 추정치이고, 이 수치는 `goldset.yaml`의
`summary.title_pass_recheck`에 기록됩니다.

- 뒤집힘 0건 → 1패스 기준이 신뢰할 만하다는 **근거**가 됩니다
- 뒤집힘이 여럿 → 1패스 기준이 너무 빡빡합니다. §3을 고치고 해당 날짜를 다시 하세요
- 안 돌리면 `sampled: 0`으로 기록됩니다. **안 한 걸 안 했다고 적는 것도 정직한 골드셋의 일부입니다**

날짜당 1회, 2패스를 끝낸 뒤에 돌리세요.

### 2.5 한 세션의 크기

**한 번에 200건을 넘기지 마세요.** 피로가 누적되면 후반부가 전부 `n`이 됩니다.
풀 1일치는 대개 한두 세션이면 끝납니다 (풀이 없던 `_0` 시절 1패스 700건은 3~4세션이었습니다).

### 4.1 서베이 판정 — 확정 (2026-08-16, 라벨링 시작 전)

**규칙: 형식이 아니라 주제로 판정하되, 읽기 문턱을 한 단계 올린다.**

1. 서베이라는 형식을 지우고 묻는다 — 이 주제의 일반 논문이었어도 무관인가?
   무관이면 **무관** (형식과 관계없이).
2. 주제가 관련이면, 그 주제가 **weight 1.0·0.9 관심사의 정면**인지 본다.
   - 정면 (그 관심사가 서베이의 주된 대상) → **관련**
   - 0.8 이하 관심사이거나 여러 관심사에 비스듬히 걸침 → **무관**. 애매하면 `m` 메모
3. 제목에 "Survey"가 없어도 초록에서 서베이로 드러나면 같은 기준.

**왜 이 규칙인가**

- §1의 기준 문장에 정직하다. 지금 M1·M2를 직접 만드는 중이라 `rag_retrieval_eval`·
  `faithfulness_hallucination`·`judge_bias` 서베이는 실제로 연다. `image_restoration`
  (0.6, 과거 프로젝트) 서베이는 열지 않는다. 1.0/0.9 vs 0.8 경계는 프로파일 작성 때
  이미 그어둔 선("직접 다뤘거나 곧 필요한" vs "인접")이라 새 자의적 기준이 아니다.
- **전부-무관으로 라벨링하면 exclude.soft의 `penalty: 0.3`을 영영 검증할 수 없다.**
  골드셋이 "서베이 = 무조건 오답"이라 말하면 M1 평가는 페널티를 키울수록 점수가
  좋아지고, M6 가중치 갱신이 프로파일의 "입문에 유용" 설계와 모순된 방향으로 간다.
  정직하게 라벨링해야 0.3이 맞는 값인지 실측된다.
- **1패스에서는 이 규칙을 적용하려 하지 말 것.** 제목만으로 "정면" 여부를 가리기
  어렵다. 서베이 제목이 코어 주제면 `k`(보류), 명백히 무관한 주제면 `n`.

이 규칙과 어긋나는 사례가 나오면 §5에 기록하고 이 절을 갱신한다.

### 4.2 VLA·구현체 에이전트 판정 — 확정 (2026-08-20, 라벨링 시작 전)

**규칙: 로봇이 나온다고 무관이 아니다. 알맹이가 방법론이면 관련.**

1. 논문의 기여가 **멀티모달 정렬 / 장기 계획·서브태스크 분해 / 메모리 / 실패 복구 /
   에이전트 평가 방법론** 중 하나면 → **관련** (`vla_embodied_agent`)
2. 기여가 **저수준 모터 제어, 하드웨어 구동, 특정 로봇 플랫폼 최적화, 자율주행**이면
   → **무관**
3. 애매하면 물어보세요 — "이 방법을 로봇이 아닌 도메인에 그대로 옮길 수 있나?"
   옮길 수 있으면 관련입니다.

**왜 바꿨나**: 프로파일 `_1`은 exclude 에 `"robotics control, manipulation"` 을 두고
VLA 논문을 감점하고 있었습니다. 그런데 VLA 논문의 알맹이는 `agent_orchestration`·
`judge_bias` 와 정면으로 겹칩니다 — 프로파일의 결함이었지 판정 기준의 문제가
아니었습니다. `profile.papers_2.yaml` 에서 관심사 `vla_embodied_agent`(weight 0.8)를
추가하고 exclude 를 저수준 제어로 좁혔습니다.

실측: 2026-08-18 수집분 1,132건 중 VLA/로봇조작 34건(3.0%). 감당 가능한 양입니다.

**양자컴퓨팅·계산생물학은 그대로 무관**입니다. 관심이 있어도 본인 프로젝트·취업
타겟과 닿지 않고 수집분의 1.1% 뿐입니다. "읽고 싶은 것"과 "이 시스템이 골라줄 것"은
분리합니다.

## 6. 알려진 한계 ★ 숨기지 말 것

포트폴리오에 이 골드셋의 수치를 쓸 때 **함께 명시해야 하는 항목**입니다.
한계를 적어두는 게 수치의 신뢰도를 낮추는 게 아니라 높입니다.

| # | 한계 | 영향 | 완화 |
|:--:|:--|:--|:--|
| 1 | **라벨러 1인** | 라벨러 간 일치도(IAA)를 계산할 수 없음 | 개인화 시스템이므로 개인 기준이 정답이라는 프레이밍이 정직함 (기획안 §11) |
| 6 | **제목·초록을 Claude가 기계번역해 병기함** (라벨러가 영어 독해에 부담을 느껴 도입) | 번역 오류·뉘앙스 손실이 판정에 영향 줄 수 있음. 단 **판정 자체는 전부 사람이 함** — 번역은 통역이지 심사가 아님 | ① 원문을 항상 병기해 수치·용어를 대조 가능하게 함 ② 번역 시 수치·모델명 원문 유지 규칙 ③ 번역 수치가 원문과 일치하는지 규칙 검사로 확인 |
| 2 | **1패스는 제목만 봄** | 제목이 불친절한 논문을 놓칠 수 있음 | **`recheck`로 누락률을 실측** (§2.4). `goldset.yaml`의 `summary.title_pass_recheck.miss_rate`가 그 수치입니다. 추정이 아니라 측정치를 쓸 수 있습니다 |
| 3 | **3일치 = 소표본** | 하루 3~7건 × 3일이면 정답이 10~20건. Hit@5의 분산이 큼 | 신뢰구간을 함께 보고, 단일 수치로 단정하지 말 것 |
| 4 | **시점 고정** | 관심사는 변함. 6개월 뒤 같은 논문을 다르게 판정할 수 있음 | 라벨링 시점을 `labeled_at` 에 기록. M6 재측정 시 골드셋 재라벨링 여부를 명시 |

| 7 | **다중 시스템 풀링 — 전수 아님** | 4조건이 모두 상위 30 밖에 둔 정답은 판정되지 않고 무관으로 셈. 풀에 기여하지 않은 새 조건은 **불리하게** 측정됨 | 무작위 50 으로 놓친 규모를 추정(`summary.pooling.estimated_missed`) · results.md 판정률(judged@10) 표 + ⚠ · 새 조건은 `python -m eval.pool --conditions` 로 덧붙이고 라벨링. 이력서에는 "4조건 풀링(깊이 30) + 무작위 50" 이라고 쓰고 **"전수 라벨링"이라고 쓰지 않음** |
