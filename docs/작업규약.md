## 4. 테스트가 진짜 검증하는지 확인하는 절차 ★

### 4.1 왜 이 절차가 필요한가 — 실제로 일어난 사건

`eval/label.py`의 라벨링 테스트 **17개가 통과하면서 아무것도 검증하지 않고 있었습니다.**

```python
# 잘못된 형태 — 기본값이 정의 시점에 바인딩됩니다
def load_candidates(date, candidates_dir: Path = CANDIDATES_DIR): ...
```

테스트가 `monkeypatch.setattr(L, "CANDIDATES_DIR", tmp)`로 갈아끼워도 함수는 **실제 `data/candidates/2026-08-12.jsonl`(719건)** 을 읽고 있었습니다. 12건을 기대한 테스트가 719건을 읽고도 초록이었던 건, 입력 키가 12개에서 끊기자 `q`로 종료돼 우연히 12건만 기록됐기 때문입니다. 고치자 `test_shuffle_actually_shuffles`가 즉시 빨간불이 됐습니다 — **그게 정상입니다.**

### 4.2 새 테스트를 쓸 때의 의무 절차 (5단계, 생략 금지)

| 단계 | 행동 | 통과 기준 |
|:--:|:--|:--|
| 1 | 테스트를 쓴다 | — |
| 2 | `$RADAR_PY -m pytest tests/test_X.py::test_Y -q` | **초록** |
| 3 | **프로덕션 코드에 결함을 일부러 심는다** (§4.3 표) | — |
| 4 | 같은 명령 재실행 | **빨강 + 실패 메시지가 심은 결함을 가리켜야 함** |
| 5 | 결함을 되돌리고 재실행 | **초록** |

3단계에서 **빨강이 안 나오면 그 테스트는 가짜입니다.** 삭제하고 다시 쓰세요.

### 4.3 결함 카탈로그 — 무엇을 심을 것인가

| 테스트가 주장하는 것 | 심을 결함 | 기대 실패 |
|:--|:--|:--|
| 경로를 monkeypatch로 갈아끼운다 | 기본 인자를 `None`→모듈 상수로 되돌린다 | 실제 `data/` 건수(719 등)가 나와야 함 |
| 3초 간격을 지킨다 | `min_interval_sec`를 0.1로 | 간격 assert 실패 |
| 단일 커넥션 | 슬롯 밖에서 요청을 연다 | 동시 카운터 ≥2 |
| 중복 0건 | `filter_unseen`을 항등함수로 | after_dedup 불일치 |
| 구형 ID 보존 | `rsplit("/", 1)[-1]`로 되돌린다 | `math.GT/` 접두사 유실 |
| `connection` 채점 제외 | `VERIFIABLE_FIELDS`에 `"connection"` 추가 | 정상 요약이 감점 |
| 검증자 계열 분리 | `assert_verifier_differs`를 ID 동등 비교로 축소 | `claude-opus-5`/`claude-haiku-4-5`가 통과해버림 |

## 7. 문서화 규약 — 주석에 무엇을 남기는가

### 7.1 주석을 **반드시** 다는 4가지 경우

| 경우 | 형식 | 예 |
|:--|:--|:--|
| 법적·약관 제약 | `# <조항 출처> <조항 번호> — <무엇을 막는가>` | `# 사람인 약관 조항 6(제휴 오인 금지) — 무료 공개여도 위반` |
| 성능이 아니라 규정 때문에 느린 코드 | `# 최적화 금지. <근거>` | `# 최적화 금지. arXiv 약관: 3초 1회 + 단일 커넥션 (델타 §D2)` |
| 안 하기로 **결정한** 것 | `# 하지 않는 이유: <근거 문서 §번호>` | `# PDF 링크를 저장하지 않는 이유: 델타 §D1` |
| 못 잡는 것을 고정한 테스트 | docstring에 "설계상 못 잡습니다" | `RuleBasedFakeVerifier`의 인과·반전 미검출 |

**형식 규칙**: 법적 근거는 **반드시 조항 번호와 함께** 씁니다. `# 약관 때문에`는 금지입니다.

**이걸 어기면 조용히 망가지는 것**: 근거 없는 `sleep(3)`은 다음 사람에게 "성능 개선 여지"로 보입니다. 병렬화하면 IP가 차단되고, 차단은 코드 변경 며칠 뒤에 나타나므로 원인 추적이 안 됩니다. 주석 한 줄이 유일한 방어선입니다.

### 7.2 문서를 새로 쓸 때

| 규칙 | 이유 |
|:--|:--|
| `docs/`는 §1.3의 번호 규칙. 기존 파일 수정 금지 | 이력 보존 |
| **추정과 실측을 구분해서 표기** ("실측: MPS 0.094s/건" vs "추정") | 02_M1환경처럼 실측이 추정을 뒤집는 일이 실제로 있었습니다 |
| 안 한 것을 안 했다고 적는다 (`sampled: 0`) | 골드셋 `title_pass_recheck`가 이 원칙의 구현입니다 |
| 수치를 적을 때 **조건을 함께** 적는다 (장치, 리비전, 날짜별 후보 수) | 조건 없는 Hit@5는 3개월 뒤 재현 불가 |

### 7.3 `eval/results.md`에 **반드시** 들어가야 하는 열

```
| 날짜 | 후보 수 | 조건 | Hit@5 | MRR | nDCG@10 | 장치 | 임베더 revision |
```

**후보 수 열이 없으면 표가 무효입니다.** 첫날 719건, 이후 약 350건으로 풀 크기가 2배 다릅니다. 큰 풀에서의 Hit@5가 구조적으로 불리하므로, 후보 수 없이 날짜 평균을 내면 해석이 왜곡됩니다.
