## 개발 환경

Python **3.11** 고정입니다 (기획안 §5). conda는 인터프리터 격리용이고, **의존성은 pip으로** 관리합니다 — Actions는 conda를 쓰지 않으므로 conda로 설치하면 로컬에만 있는 패키지가 생겨 CI에서만 터집니다.

```bash
conda create -y -n radar python=3.11 && conda activate radar && pip install -r requirements.txt
```

M1 평가를 로컬에서 돌리려면 추가로 (약 1GB — **Actions에는 설치하지 않습니다**, 기획안 §5.1-(1)):

```bash
pip install -r requirements-eval.txt
```

모델은 `eval/models.yaml`에 **커밋 해시로 리비전이 고정**돼 있습니다. 리비전 없이 로드하면 sentence-transformers가 미머지 PR에서 가중치를 받아갑니다 — [docs/02_M1환경.md](./docs/02_M1환경.md) §3.1.

## 실행

```bash
python -m src.core.pipeline --channel papers --stage collect
```

연휴 등으로 48시간 창에 300건이 안 차면 실패가 아닙니다. `--window-hours 72`로 넓히세요 — 넓힌 사실은 원장 `params.window_hours`에 남습니다.

```bash
pytest
```

기본 실행은 네트워크를 쓰지 않습니다. 실제 arXiv를 때리는 DoD 테스트는 `pytest -m network`로 분리돼 있습니다.

## 골드셋 라벨링

기준을 먼저 읽고([docs/라벨링_기준.md](./docs/라벨링_기준.md)) 시작하세요.

```bash
python -m eval.label triage --date 2026-08-12
```

1패스는 제목만 보고 거르고(`n`/`k`), 2패스(`review`)에서 보류분의 초록을 읽습니다. `recheck`는 1패스에서 버린 것 중 표본을 다시 읽어 **누락률을 실측**합니다. 언제든 `q`로 나가면 이어서 할 수 있습니다.

## ★ 운영 규칙 — arXiv (델타 §D2)

**로컬에서 수집을 돌리기 전 Actions 스케줄을 끌 것. 겹치면 arXiv 약관 위반이며 IP 차단 대상입니다.**

3초 1회·단일 커넥션 제약은 "본인 통제 하의 **모든 머신에 합산** 적용"됩니다. 코드의 파일락(`data/.arxiv_lock`)은 같은 머신의 프로세스만 직렬화합니다. 로컬 맥과 Actions 러너는 서로 다른 머신이라 락으로 못 묶습니다 — 그건 이 규칙으로만 막힙니다.

## 파일 번호 규칙

문서는 덮어쓰지 않고 끝에 `_N`을 붙여 새 파일로 저장합니다. **읽을 때는 각 이름의 최고 번호 하나만** 읽으세요. 소스코드와 `CLAUDE.md`·`README.md`·`.gitignore`는 예외로 덮어씁니다.

설정 파일도 이 규칙을 따르므로 **코드가 경로를 하드코딩하면 구버전을 읽습니다.** `src/core/config.py`의 `resolve_profile()`이 최고 번호를 해석하고, 실제로 읽은 경로를 원장에 남깁니다 (결정_M0 §4).
